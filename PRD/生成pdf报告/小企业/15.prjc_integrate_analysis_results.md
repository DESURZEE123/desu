# AI分析结果 · 功能整合

> L1 · `moduleIndex: 15` · 上游：尽调全量入参 · 下游：`prjc_style_render`  
> 仅输出结构化 JSON（无 HTML）；完整报告须经 L0（`prjc_integrate_report`）调度。

**职责：** 从入参提取 `analysisResults`，按 `analysisType` 分组排序并标注 `displayType: analysisList`。不做业务分析、不改写 AI 结论 Markdown 原文、不做 HTML 渲染。仅小企业（`prjc-slb`）；字段结构固定，不做尽调系统分支。

---

## 一、模块标识

| 字段 | 值 |
| ---- | -- |
| `moduleIndex` | `15` |
| `moduleKey` | `analysis_results` |
| `moduleName` | `AI分析结果` |

---

## 二、数据来源

| 路径 | 说明 |
| ---- | ---- |
| `analysisResults[]` | 模块主数据：AI 分析结果列表 |
| `.analysisType` | 分析类型（分组标题） |
| `.customerName` | 客户名称（司法分析按客户分行；流水分析可为空） |
| `.analysisConclusion` | 分析结论（**Markdown 原文**，PDF 唯一展示内容 → `conclusion`） |
| `.customerNo` | 客户编号（仅数据匹配，**不输出**） |
| `.taskStatus` / `.pkAnalysisResult` 等 | 仅数据匹配，不输出 |

**PDF 不输出：** `analysisDetail`（L1 **不提取**）；「查看详情」链接；`customerNo` / `taskStatus` / `taskId` / 时间戳 / 主键。

---

## 三、整模块门禁（校验）

| # | 条件 | 结果 |
| -: | ---- | ---- |
| 1 | `analysisResults` 缺失 / `null` / 非数组 / 长度 0 | **整模块不输出**（L0 跳过），不中断其它模块 |

通过后：按 §四分组；组内保留入参原始顺序；仅输出入参中**实际出现**的 `analysisType`，未出现的不输出空分组。

---

## 四、展示与格式化（校验）

模块顶栏：「AI分析结果」。每个 `analysisType` 输出 **1 个** `analysisList` block。

### 4.1 分组顺序（`analysisType`）

| 顺序 | analysisType | blockKey | 说明 |
| :--: | ------------ | -------- | ---- |
| 1 | `项目流水分析` | `cashflow_analysis` | 项目级；通常无 `customerName` |
| 2 | `项目司法分析` | `judicial_analysis` | 按客户分行；有 `customerName` 时展示实体标题 |

上表未列出的 `analysisType`：按首次出现顺序追加在固定类型之后；`label` 取原文；`blockKey` = `analysis_type_{序号}`。

### 4.2 `analysisList` 结构

| 字段 | 说明 |
| ---- | ---- |
| `label` | `analysisType` 原文（分组标题） |
| `emptyText` | 固定 `暂无分析结果`（`items` 空时；正常分组不会为空） |
| `items[]` | 该类型下条目，按入参顺序 |
| `items[].customerName` | 有值 → 蓝色实体标题；空 / `null` → 不渲染标题行 |
| `items[].conclusion` | `analysisConclusion` 规范化后的 Markdown；**禁止**预渲染为 HTML |

### 4.3 结论空值规范化（`conclusion`）

| 原值 | 规范化结果 | L2 表现 |
| ---- | ---------- | ------- |
| `null` / `undefined` / `""` | `null`（字段不传或传 null） | 结论区「—」 |
| `"{}"`（空 JSON 对象字符串） | `null` | 同上 |
| 仅空白字符 | `null` | 同上 |
| 其他字符串 | **原样透传**（保留 Markdown） | L2 按 Markdown → HTML |

- `conclusion` 为空：仍保留该 `item`，L2 展示「—」
- `customerName` 为空：不输出实体标题（流水分析场景）

### 4.4 字段映射

| 接口字段 | 输出 | 备注 |
| -------- | :--: | ---- |
| `analysisType` | ✅ | → block.`label` |
| `customerName` | 条件 | 有值才展示实体标题 |
| `analysisConclusion` | ✅ | → `conclusion`，Markdown |
| `analysisDetail` | — | **不输出** |
| `customerNo` / `taskStatus` / 主键等 | — | 不输出 |

其它：不改写结论；输出不得含 HTML；必须带 `moduleIndex: 15`。

**L2 协作：** 唯一展示类型 `analysisList`；Markdown 渲染见 `prjc_style_render.md`；L1 不输出 `detail` / `html`。

## 五、输出示例

```json
{
  "moduleIndex": 15,
  "moduleName": "AI分析结果",
  "moduleKey": "analysis_results",
  "blocks": [
    {
      "blockKey": "cashflow_analysis",
      "label": "项目流水分析",
      "displayType": "analysisList",
      "emptyText": "暂无分析结果",
      "items": [
        { "customerName": null, "conclusion": "**流水分析结论：** 该承租人仅提供…" }
      ]
    },
    {
      "blockKey": "judicial_analysis",
      "label": "项目司法分析",
      "displayType": "analysisList",
      "emptyText": "暂无分析结果",
      "items": [
        { "customerName": "苏州工业园区昌源工贸有限公司", "conclusion": null },
        { "customerName": "肖令权", "conclusion": "## 模块七：综合评分与建议\n\n- **综合评分**：低风险\n…" }
      ]
    }
  ]
}
```

> 输入中 `analysisConclusion: "{}"` → 输出 `conclusion: null`；`analysisDetail` 不进入输出。分组顺序：流水 → 司法（固定类型优先）。
